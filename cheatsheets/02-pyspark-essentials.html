1. Basic DataFrame Operations

â–¼

Fundamental operations for creating, reading, writing, and manipulating DataFrames in PySpark. These operations form the foundation of any ELT pipeline and are essential for data ingestion and basic transformations.

Creating and Reading DataFrames

# Creating DataFrame from Python data structures
from pyspark.sql import SparkSession
from pyspark.sql.functions import *
from pyspark.sql.types import *

# Initialize SparkSession
spark = SparkSession.builder.appName("ELT_Pipeline").getOrCreate()

# Create DataFrame from list of dictionaries
data = [{"name": "Alice", "age": 25}, {"name": "Bob", "age": 30}]
df = spark.createDataFrame(data)

# Reading CSV File with comprehensive options
df_csv = spark.read \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .option("multiLine", "true") \
    .csv("path/to/file.csv")

# Reading JSON File - handles nested structures automatically
df_json = spark.read.json("path/to/file.json")

# Reading Parquet File - most efficient format for analytics
df_parquet = spark.read.parquet("path/to/file.parquet")
  • What it does: Creates DataFrames from various sources and formats
  • When to use: Data ingestion phase of ELT pipelines
  • Performance tip: Parquet is fastest for large datasets; CSV inference can be expensive on big files
  • Edge case: Schema inference works well for small files but can timeout on large datasets

Basic DataFrame Operations

# Show DataFrame content
df.show()  # Shows first 20 rows
df.show(50, truncate=False)  # Show 50 rows without truncating

# Print Schema - crucial for understanding data structure
df.printSchema()

# Column Selection - select specific columns
df_selected = df.select("column1", "column2")

# Filtering Rows - apply conditions to filter data
df_filtered = df.filter(df["column"] > value)

# Adding a New Column - create computed columns
df_with_new_col = df.withColumn("newColumn", col("existing_col") * 2)

# Renaming a Column
df_renamed = df.withColumnRenamed("oldName", "newName")

# Dropping a Column
df_dropped = df.drop("column")

# Describe Data - get statistical summary
df.describe().show()

# Counting Rows - get total record count
row_count = df.count()

# Get distinct values
df_distinct = df.select("column").distinct()

# Sample Data - get random sample for testing
df_sample = df.sample(withReplacement=False, fraction=0.1, seed=42)
  • What it does: Performs basic data exploration and transformation operations
  • When to use: Data profiling, initial exploration, and simple transformations
  • Performance considerations: count() and show() trigger actions; use sparingly in production
  • Best practice: Always check schema before processing to avoid type errors

Writing DataFrames

# Writing DataFrame to CSV
df.write \
    .mode("overwrite") \
    .option("header", "true") \
    .csv("path/to/output")

# Writing DataFrame to JSON with compression
df.write \
    .mode("append") \
    .option("compression", "gzip") \
    .json("path/to/output")

# Writing DataFrame to Parquet with partitioning
df.write \
    .mode("overwrite") \
    .partitionBy("year", "month") \
    .parquet("path/to/output")
  • What it does: Saves DataFrames to various file formats and destinations
  • When to use: End of ELT pipeline or intermediate data storage
  • Performance tip: Partitioning improves query performance for time-series data
  • Gotcha: overwrite mode deletes entire directory, not just matching partitions

2. Advanced Data Manipulation

â–¼

Complex data transformation operations including joins, unions, pivots, and window functions. These operations are crucial for data integration and advanced analytics in ELT pipelines.

Joining DataFrames

# Basic join operations
df1 = spark.createDataFrame([(1, "Alice"), (2, "Bob")], ["id", "name"])
df2 = spark.createDataFrame([(1, 1000), (2, 2000)], ["id", "salary"])

# Inner join (default) - only matching records
df_inner = df1.join(df2, "id")

# Left join - all records from left DataFrame
df_left = df1.join(df2, "id", "left")

# Complex join with multiple conditions
df_complex = df1.alias("a").join(
    df2.alias("b"),
    (col("a.id") == col("b.id")) & (col("b.salary") > 1500),
    "inner"
)
  • What it does: Combines data from multiple DataFrames based on common keys
  • When to use: Data integration, enrichment, and relationship analysis
  • Performance consideration: Join operations can be expensive; consider broadcast joins for small tables
  • Best practice: Use aliases when joining tables with overlapping column names

Union and Window Operations

# Union DataFrames - combine rows from multiple DataFrames
df_union = df1.union(df2)

# Pivot Table - convert rows to columns
df_pivot = df.groupBy("category") \
    .pivot("month") \
    .agg(sum("sales"))

# Window Functions for advanced analytics
from pyspark.sql.window import Window

windowSpec = Window.partitionBy("department").orderBy("salary")
df_windowed = df.withColumn("rank", rank().over(windowSpec))

# DataFrame to RDD conversion (rare but sometimes needed)
rdd = df.rdd

# RDD to DataFrame conversion
df_from_rdd = rdd.toDF()

# Caching DataFrame for reuse
df.cache()

# Broadcast Join for performance
from pyspark.sql.functions import broadcast
df_broadcast = large_df.join(broadcast(small_df), "key")
  • What it does: Performs advanced data combination and analytical operations
  • When to use: Complex analytics, data aggregation, and performance optimization
  • Performance tip: Broadcast joins are much faster for small tables (< 200MB)
  • Edge case: Window functions can be memory-intensive with large partitions

3. Handling Missing and Duplicate Data

â–¼

Essential data quality operations for cleaning and preparing data. Missing and duplicate data are common issues in real-world datasets that must be addressed before analysis.

# Dropping Rows with Null Values
df_no_nulls = df.na.drop()  # Drop rows with any null values
df_threshold = df.na.drop(thresh=2)  # Keep rows with at least 2 non-null values

# Filling Null Values with different strategies
df_filled = df.na.fill(0)  # Fill all nulls with 0
df_filled_dict = df.na.fill({"age": 0, "name": "Unknown"})  # Column-specific fills

# Dropping Duplicate Rows
df_deduped = df.dropDuplicates()
df_deduped_subset = df.dropDuplicates(["id", "date"])  # Based on specific columns

# Replacing Values - useful for data standardization
df_replaced = df.na.replace(["old_value"], ["new_value"])
  • What it does: Handles missing data and removes duplicates from datasets
  • When to use: Data cleaning phase before analysis or modeling
  • Best practice: Understand your data before choosing fill strategy (mean, median, mode)
  • Performance note: dropDuplicates() is expensive - use specific columns when possible

4. Data Transformation

â–¼

Core transformation operations including User Defined Functions (UDFs), string operations, date/time functions, and conditional logic. These operations enable custom business logic and data standardization.

User Defined Functions (UDFs)

# UDF (User Defined Function) for custom transformations
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

def custom_function(value):
    return value.upper() if value else "UNKNOWN"

# Register UDF
custom_udf = udf(custom_function, StringType())
df_transformed = df.withColumn("upper_name", custom_udf(col("name")))

# Pandas UDF for vectorized operations (much faster)
from pyspark.sql.functions import pandas_udf
import pandas as pd

@pandas_udf("double")
def pandas_multiply(s: pd.Series) -> pd.Series:
    return s * 2

df_vectorized = df.withColumn("doubled_salary", pandas_multiply(col("salary")))
  • What it does: Enables custom Python functions to be applied to DataFrame columns
  • When to use: Complex business logic that can't be expressed with built-in functions
  • Performance tip: Pandas UDFs are 3-10x faster than regular Python UDFs
  • Gotcha: UDFs can't be optimized by Catalyst - use built-in functions when possible

Built-in Functions

# String Operations
df_string = df.select(
    upper(col("name")).alias("name_upper"),
    lower(col("name")).alias("name_lower"),
    length(col("name")).alias("name_length")
)

# Date and Time Functions
df_datetime = df.select(
    current_date().alias("today"),
    current_timestamp().alias("now"),
    year(col("birth_date")).alias("birth_year")
)

# Numeric Functions
df_numeric = df.select(
    abs(col("balance")).alias("abs_balance"),
    sqrt(col("area")).alias("sqrt_area"),
    round(col("price"), 2).alias("rounded_price")
)

# Conditional Expressions
df_conditional = df.select(
    when(col("age") < 18, "Minor")
    .when(col("age") < 65, "Adult")
    .otherwise("Senior").alias("age_group")
)

# Type Casting
df_casted = df.withColumn("age_string", col("age").cast("string"))

# Explode Function (Array to Rows) - flatten arrays
df_exploded = df.withColumn("exploded_tags", explode(col("tags_array")))
  • What it does: Applies built-in Spark functions for common transformations
  • When to use: Standard data transformations, type conversions, conditional logic
  • Performance advantage: Built-in functions are optimized by Catalyst optimizer
  • Best practice: Always prefer built-in functions over UDFs for performance

Advanced Transformations

# Handling JSON Columns
from pyspark.sql.functions import from_json, schema_of_json

# Define JSON schema
json_schema = StructType([
    StructField("id", IntegerType(), True),
    StructField("name", StringType(), True)
])

# Parse JSON column
df_json_parsed = df.withColumn(
    "parsed_data", 
    from_json(col("json_column"), json_schema)
)

# Window Functions (Rank, Lead, Lag)
from pyspark.sql.functions import rank, lead, lag

windowSpec = Window.partitionBy("department").orderBy("salary")
df_analytics = df.withColumn("rank", rank().over(windowSpec)) \
    .withColumn("next_salary", lead("salary", 1).over(windowSpec)) \
    .withColumn("prev_salary", lag("salary", 1).over(windowSpec))
  • What it does: Handles complex data structures and advanced analytical functions
  • When to use: JSON data processing, time-series analysis, ranking operations
  • Performance note: Window functions require data shuffling - partition wisely
  • Use case: Essential for analytics and reporting applications

5. Data Profiling

â–¼

Statistical analysis and data exploration operations to understand data characteristics, distributions, and relationships. Critical for data quality assessment and exploratory data analysis.

# Column Value Counts - frequency analysis
value_counts = df.groupBy("category").count().orderBy(desc("count"))

# Summary Statistics for Numeric Columns
summary_stats = df.describe()  # count, mean, stddev, min, max

# Correlation Between Columns - measure linear relationships
correlation = df.stat.corr("column1", "column2")

# Crosstabulation and Contingency Tables - analyze categorical relationships
crosstab = df.stat.crosstab("column1", "column2")

# Frequent Items in Columns - find most common values
frequent_items = df.stat.freqItems(["column1", "column2"])

# Approximate Quantile Calculation - percentiles for large datasets
quantiles = df.approxQuantile("salary", [0.25, 0.5, 0.75], 0.01)
print(f"25th: {quantiles[0]}, 50th: {quantiles[1]}, 75th: {quantiles[2]}")

# Advanced profiling
def profile_dataframe(df):
    """Comprehensive data profiling function"""
    print(f"Shape: ({df.count()}, {len(df.columns)})")
    print("Null counts:")
    df.select([count(when(col(c).isNull(), c)).alias(c) for c in df.columns]).show()
    
    # Data types
    print("Data types:")
    for col_name, col_type in df.dtypes:
        print(f"  {col_name}: {col_type}")
  • What it does: Provides statistical insights and data quality metrics
  • When to use: Initial data exploration, data quality assessment, before modeling
  • Performance tip: approxQuantile is much faster than exact percentiles
  • Best practice: Always profile new datasets to understand data distribution

8. Working with Large Data

â–¼

Optimization strategies and techniques for handling large-scale data processing efficiently, including partitioning, caching, and skew handling.

# Partitioning Data for parallel processing
df_repartitioned = df.repartition(8)  # Increase partitions for more parallelism
df_repartitioned_by_col = df.repartition("department")  # Partition by column

# Coalesce Partitions - reduce partition count without shuffle
df_coalesced = df.coalesce(4)  # Reduce to 4 partitions

# Reading Data in Chunks for streaming
streaming_df = spark.readStream \
    .option("maxFilesPerTrigger", 1) \
    .csv("path/to/streaming/data/")

# Optimizing Data for Skewed Joins
# Method 1: Repartition skewed column
df_optimized = df.repartition("skewed_column")

# Method 2: Broadcast hint for skewed joins
df_result = df1.join(df2.hint("broadcast"), "join_key")

# Method 3: Salt technique for extreme skew
from pyspark.sql.functions import rand

df_salted = df.withColumn("salt", (rand() * 100).cast("int"))
skewed_df_salted = skewed_df.withColumn("salt", lit(0))

# Join with salted keys
result = df_salted.join(
    skewed_df_salted,
    (col("df1.key") == col("df2.key")) & (col("df1.salt") == col("df2.salt"))
)

# Memory management
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.adaptive.skewJoin.enabled", "true")
spark.conf.set("spark.serializer", "org.apache.spark.serializer.KryoSerializer")
  • What it does: Optimizes Spark operations for large-scale data processing
  • When to use: Performance tuning, handling data skew, memory optimization
  • Key insight: Right partitioning strategy can make 10x performance difference
  • Advanced technique: Salting helps with extreme data skew scenarios

9. Spark SQL

â–¼

SQL interface for Spark operations, enabling SQL-familiar users to work with DataFrames and integration with BI tools and existing SQL workflows.

# Running SQL Queries on DataFrames
# First, create temporary view
df.createOrReplaceTempView("employees")

# Execute SQL queries
sql_result = spark.sql("""
    SELECT department, 
           AVG(salary) as avg_salary,
           COUNT(*) as employee_count
    FROM employees 
    WHERE age > 25
    GROUP BY department
    ORDER BY avg_salary DESC
""")

# Registering UDF for SQL Queries
def categorize_salary(salary):
    return "High" if salary > 80000 else "Low"

spark.udf.register("categorize_salary", categorize_salary)

# Use UDF in SQL
result = spark.sql("""
    SELECT name, salary, categorize_salary(salary) as salary_category
    FROM employees
""")

# Using SQL Functions in DataFrames
from pyspark.sql.functions import expr

df_with_sql = df.withColumn(
    "bonus_calculation",
    expr("CASE WHEN salary > 50000 THEN salary * 0.1 ELSE salary * 0.05 END")
)

# Complex SQL operations
complex_query = spark.sql("""
    WITH ranked_employees AS (
        SELECT *,
               ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) as rank
        FROM employees
    ),
    department_stats AS (
        SELECT department,
               AVG(salary) as avg_salary,
               STDDEV(salary) as stddev_salary
        FROM employees
        GROUP BY department
    )
    SELECT e.name, e.department, e.salary, e.rank, d.avg_salary
    FROM ranked_employees e
    JOIN department_stats d ON e.department = d.department
    WHERE e.rank <= 3
""")
  • What it does: Enables SQL syntax for DataFrame operations and complex analytics
  • When to use: Complex analytical queries, team members familiar with SQL
  • Performance benefit: Catalyst optimizer works on both DataFrame API and SQL
  • Integration advantage: Easy to integrate with BI tools and SQL-based workflows

10. Machine Learning and Advanced Analytics

â–¼

MLlib integration for scalable machine learning on big data, including feature engineering, model training, evaluation, and deployment pipelines.

# VectorAssembler for Feature Vectors
from pyspark.ml.feature import VectorAssembler

assembler = VectorAssembler(
    inputCols=["age", "salary", "experience"],
    outputCol="features"
)

# StandardScaler for Feature Scaling
from pyspark.ml.feature import StandardScaler

scaler = StandardScaler(
    inputCol="features",
    outputCol="scaledFeatures",
    withStd=True,
    withMean=True
)

# Building a Machine Learning Pipeline
from pyspark.ml import Pipeline
from pyspark.ml.classification import LogisticRegression

lr = LogisticRegression(featuresCol="scaledFeatures", labelCol="target")

pipeline = Pipeline(stages=[assembler, scaler, lr])

# Train-Test Split
train, test = df.randomSplit([0.8, 0.2], seed=42)

# Model Fitting and Predictions
model = pipeline.fit(train)
predictions = model.transform(test)

# Cross-Validation for Model Tuning
from pyspark.ml.tuning import CrossValidator, ParamGridBuilder
from pyspark.ml.evaluation import BinaryClassificationEvaluator

paramGrid = ParamGridBuilder() \
    .addGrid(lr.regParam, [0.01, 0.1, 1.0]) \
    .addGrid(lr.elasticNetParam, [0.0, 0.5, 1.0]) \
    .build()

crossval = CrossValidator(
    estimator=pipeline,
    estimatorParamMaps=paramGrid,
    evaluator=BinaryClassificationEvaluator(),
    numFolds=5
)

# Hyperparameter Tuning
cv_model = crossval.fit(train)
best_predictions = cv_model.transform(test)
  • What it does: Enables scalable machine learning on large datasets
  • When to use: Predictive modeling, classification, regression on big data
  • Scalability advantage: MLlib algorithms are designed for distributed computing
  • Pipeline benefit: Ensures consistent preprocessing in training and prediction

Performance Best Practices Summary

â–¼
  • Data Formats: Use Parquet or Delta Lake for analytical workloads
  • Partitioning: Partition data by commonly filtered columns (date, region)

ANSI Standard Functions - SQL vs PySpark

SQL (ANSI Standard)

-- String functions
SELECT 
    UPPER(name) as upper_name,
    LOWER(email) as lower_email,
    LENGTH(description) as desc_len,
    SUBSTRING(name FROM 1 FOR 10) as short_name,
    TRIM(BOTH ' ' FROM name) as trimmed,
    POSITION('@' IN email) as at_pos,
    
    -- Window functions
    RANK() OVER (
        PARTITION BY department 
        ORDER BY salary DESC
    ) as salary_rank
FROM employees;

PySpark DataFrame API

from pyspark.sql import functions as F
from pyspark.sql.window import Window

df.select(
    # String functions
    F.upper("name").alias("upper_name"),
    F.lower("email").alias("lower_email"),
    F.length("description").alias("desc_len"),
    F.substring("name", 1, 10).alias("short_name"),
    F.trim("name").alias("trimmed"),
    F.instr("email", "@").alias("at_pos"),
    
    # Window functions
    F.rank().over(
        Window.partitionBy("department")
              .orderBy(F.desc("salary"))
    ).alias("salary_rank")
)

ANSI Standard Joins - SQL vs PySpark

SQL (ANSI-92 Joins)

-- ANSI standard join syntax
SELECT c.customer_name, o.order_date, p.product_name
FROM customers c
    INNER JOIN orders o ON c.customer_id = o.customer_id
    LEFT OUTER JOIN order_items oi ON o.order_id = oi.order_id  
    RIGHT OUTER JOIN products p ON oi.product_id = p.product_id
    FULL OUTER JOIN categories cat ON p.category_id = cat.category_id
WHERE o.order_date >= DATE '2024-01-01';

PySpark DataFrame API

result = customers.alias("c") \

          "right_outer") \

          F.col("p.category_id") == F.col("cat.category_id"),
