ðŸŒ Namespaces and Scope

â–¼

Namespaces are containers for identifiers (names) that help organize code and prevent naming conflicts. Understanding scope determines where variables can be accessed in your code.

What is a Namespace?

A namespace is a mapping from names to objects. It's essentially a dictionary where the keys are identifier names and values are the objects they refer to.

# Demonstrating different namespaces and their relationships

# Global namespace - available throughout the module
global_variable = "I'm in the global namespace"

def outer_function():
    """
    This function demonstrates enclosing (nonlocal) scope.
    Variables defined here are in the enclosing scope for inner functions.
    """
    # Enclosing namespace - available to inner functions
    enclosing_variable = "I'm in the enclosing namespace"
    
    def inner_function():
        """
        This inner function demonstrates local scope and accessing
        variables from different namespace levels.
        """
        # Local namespace - only available within this function
        local_variable = "I'm in the local namespace"
        
        # Access variables from different namespaces
        print("Local:", local_variable)           # Local scope
        print("Enclosing:", enclosing_variable)   # Enclosing scope  
        print("Global:", global_variable)        # Global scope
        print("Built-in:", len([1, 2, 3]))      # Built-in scope (len function)
    
    inner_function()

# Demonstrate namespace inspection
print("Global namespace keys:", list(globals().keys()))
print("Local namespace in function:", end=" ")
outer_function()

# Built-in namespace - always available
import builtins
print("Built-in functions available:", [name for name in dir(builtins) if not name.startswith('_')][:10])
  • Built-in namespace: Contains built-in functions like len(), print(), str()
  • Global namespace: Module-level variables and functions
  • Enclosing namespace: Variables in outer functions (for nested functions)
  • Local namespace: Variables inside the current function
  • LEGB Rule: Python searches for variables in Local â†’ Enclosing â†’ Global â†’ Built-in order

Variable Scope and the LEGB Rule

Python follows the LEGB rule when resolving variable names: Local, Enclosing, Global, Built-in scopes are searched in that order.

# Comprehensive example demonstrating variable scope resolution

# Global scope variable
name = "Global Alice"

def demonstrate_scope():
    """
    Function showing how Python resolves variable names using LEGB rule.
    Demonstrates local variables, global keyword, and nonlocal keyword.
    """
    # Local variable shadows the global one
    name = "Local Bob"
    
    def nested_function():
        """
        Nested function demonstrating enclosing scope access
        and the nonlocal keyword for modifying enclosing variables.
        """
        # This would create a new local variable
        # name = "Nested Charlie"
        
        # Instead, we can modify the enclosing scope variable
        nonlocal name
        name = "Modified Bob from nested function"
        
        print(f"Inside nested_function: {name}")
    
    def global_modifier():
        """
        Function demonstrating the global keyword for modifying
        global scope variables from within a function.
        """
        global name  # Refer to global variable, not local
        name = "Modified Global Alice"
        print(f"Modified global variable: {name}")
    
    print(f"Before nested call: {name}")
    nested_function()
    print(f"After nested call: {name}")
    
    print(f"Global variable before modification: {globals()['name']}")
    global_modifier()

# Demonstrate scope behavior
print(f"Initial global: {name}")
demonstrate_scope()
print(f"Final global: {name}")

# Example of scope-related gotchas
def scope_gotcha_example():
    """
    Common gotcha: UnboundLocalError when trying to modify
    a global variable without declaring it as global.
    """
    counter = 0  # Local variable
    
    def increment():
        # This would cause UnboundLocalError without nonlocal
        nonlocal counter
        counter += 1
        return counter
    
    return increment

# Create a closure that maintains state
counter_func = scope_gotcha_example()
print(f"First call: {counter_func()}")   # 1
print(f"Second call: {counter_func()}")  # 2
  • Variable shadowing: Local variables hide global ones with the same name
  • global keyword: Allows modification of global variables inside functions
  • nonlocal keyword: Allows modification of enclosing scope variables
  • Closures: Inner functions can capture and remember enclosing scope variables

ðŸ”§ Functions in Detail

â–¼

Functions are first-class objects in Python that encapsulate reusable code. They can accept parameters, return values, and be passed around like any other object.

Function Definition and Return Values

Functions are defined using the def keyword and can return values using the return statement. Without an explicit return, functions return None.

# Comprehensive function examples showing different return patterns

def basic_function():
    """
    Basic function with no parameters or return value.
    Implicitly returns None.
    """
    print("This function performs an action but returns None")
    # Implicit: return None

def simple_calculator(a, b, operation="add"):
    """
    Function demonstrating parameters, default values, and explicit returns.
    
    Args:
        a (float): First number
        b (float): Second number  
        operation (str): Operation to perform ("add", "subtract", "multiply", "divide")
        
    Returns:
        float: Result of the calculation
        
    Raises:
        ValueError: If operation is not supported
        ZeroDivisionError: If dividing by zero
    """
    if operation == "add":
        return a + b
    elif operation == "subtract":
        return a - b
    elif operation == "multiply":
        return a * b
    elif operation == "divide":
        if b == 0:
            raise ZeroDivisionError("Cannot divide by zero")
        return a / b
    else:
        raise ValueError(f"Unsupported operation: {operation}")

def multiple_returns(numbers):
    """
    Function returning multiple values (actually returns a tuple).
    Demonstrates tuple unpacking and multiple assignment.
    
    Args:
        numbers (list): List of numbers to analyze
        
    Returns:
        tuple: (sum, average, min, max) of the numbers
    """
    if not numbers:
        return 0, 0, None, None
    
    total = sum(numbers)
    average = total / len(numbers)
    minimum = min(numbers)
    maximum = max(numbers)
    
    # Multiple values are automatically packed into a tuple
    return total, average, minimum, maximum

# Function usage examples
print("Basic function result:", basic_function())  # None

# Simple calculator usage
result = simple_calculator(10, 5, "multiply")
print(f"10 * 5 = {result}")

# Multiple return values - tuple unpacking
numbers = [1, 5, 3, 9, 2, 7]
total, avg, min_val, max_val = multiple_returns(numbers)
print(f"Numbers: {numbers}")
print(f"Sum: {total}, Average: {avg:.2f}, Min: {min_val}, Max: {max_val}")

# Alternative: receive as tuple
stats = multiple_returns(numbers)
print(f"All statistics: {stats}")
  • Implicit return: Functions without explicit return statement return None
  • Multiple returns: Python packs multiple return values into a tuple
  • Tuple unpacking: Multiple variables can receive multiple return values
  • Docstrings: Use triple quotes for function documentation following PEP 257

Parameters vs Arguments: *args and **kwargs

Parameters are defined in the function definition, while arguments are the actual values passed when calling the function. *args and **kwargs allow functions to accept variable numbers of arguments.

# Comprehensive demonstration of parameters, arguments, *args, and **kwargs

def parameter_examples(
    required_param,           # Required positional parameter
    default_param="default",  # Parameter with default value
    *args,                   # Variable positional arguments (tuple)
    keyword_only_param,      # Keyword-only parameter (after *args)
    **kwargs                 # Variable keyword arguments (dictionary)
):
    """
    Function demonstrating all parameter types in Python.
    
    Args:
        required_param: Must be provided when calling the function
        default_param: Optional parameter with default value
        *args: Variable number of positional arguments
        keyword_only_param: Must be passed as keyword argument
        **kwargs: Variable number of keyword arguments
    """
    print(f"Required parameter: {required_param}")
    print(f"Default parameter: {default_param}")
    print(f"Positional args (*args): {args}")
    print(f"Keyword-only parameter: {keyword_only_param}")
    print(f"Keyword args (**kwargs): {kwargs}")
    print("-" * 50)

# Different ways to call the function
print("Call 1: Minimal required arguments")
parameter_examples("hello", keyword_only_param="required")

print("\nCall 2: With additional positional and keyword arguments")
parameter_examples(
    "hello",                    # required_param
    "custom_default",          # default_param
    1, 2, 3,                   # *args
    keyword_only_param="keyword",
    extra_arg1="value1",       # **kwargs
    extra_arg2="value2"
)

def flexible_data_processor(*data_sources, output_format="json", **processing_options):
    """
    Practical example: A data processing function that can handle
    multiple data sources with various processing options.
    
    Args:
        *data_sources: Variable number of data source paths
        output_format: Format for output data (keyword-only)

    if processing_options:
        print("Processing options:")
        for key, value in processing_options.items():
            print(f"  {key}: {value}")
    
    # Simulate processing
    return f"Processed {len(data_sources)} sources to {output_format}"

  • Parameters: Variable names in function definition (placeholders)
  • Arguments: Actual values passed when calling function
  • *args: Collects extra positional arguments into a tuple
  • **kwargs: Collects extra keyword arguments into a dictionary
  • Keyword-only: Parameters after *args must be passed as keyword arguments
  • Argument unpacking: Use * and ** to unpack collections as arguments

ðŸ—ï¸ Classes and Object-Oriented Programming

Classes are blueprints for creating objects. They encapsulate data (attributes) and behavior (methods) into reusable units, forming the foundation of object-oriented programming.

What is a Class? - __init__, Attributes, and Methods

A class defines a new type of object with its own attributes (data) and methods (functions). The __init__ method is a special method that initializes new instances.

# Comprehensive class example demonstrating all key concepts

class DataProcessor:
    """
    A class demonstrating all fundamental OOP concepts in Python.
    This class processes data with various transformation methods.
    """
    
    # Class variable - shared by all instances
    supported_formats = ["csv", "json", "parquet", "excel"]
    total_processors_created = 0
    
    def __init__(self, name, default_format="csv", max_size_mb=100):
        """
        Initialize a new DataProcessor instance.
        
        Args:
            name (str): Name identifier for this processor
            default_format (str): Default data format to use
            max_size_mb (int): Maximum file size in MB to process
        """
        # Instance variables - unique to each instance
        self.name = name
        self.default_format = default_format
        self.max_size_mb = max_size_mb
        self.processed_files = []  # Track processed files
        self.is_active = True
        
        # Update class variable
        DataProcessor.total_processors_created += 1
        
        print(f"Created DataProcessor '{name}' (#{DataProcessor.total_processors_created})")
    
    # Instance method - operates on instance data, has access to self
    def process_file(self, file_path, format=None):
        """
        Process a single data file.
        
        Args:
            file_path (str): Path to the file to process
            format (str, optional): Override default format
            
        Returns:
            dict: Processing result with status and metadata
        """
        if not self.is_active:
            return {"status": "error", "message": "Processor is inactive"}
        
        # Use provided format or fall back to default
        file_format = format or self.default_format
        
        if file_format not in self.supported_formats:
            return {
                "status": "error", 
                "message": f"Unsupported format: {file_format}"
            }
        
        # Simulate processing
        result = {
            "status": "success",
            "file_path": file_path,
            "format": file_format,
            "processor_name": self.name,
            "file_size_mb": 25  # Simulated
        }
        
        # Update instance state
        self.processed_files.append(result)
        
        return result
    
    # Instance method that modifies object state
    def get_processing_stats(self):
        """
        Get statistics about files processed by this instance.
        
        Returns:
            dict: Statistics about processed files
        """
        if not self.processed_files:
            return {"total_files": 0, "total_size_mb": 0}
        
        total_files = len(self.processed_files)
        total_size = sum(file["file_size_mb"] for file in self.processed_files)
        
        return {
            "processor_name": self.name,
            "total_files": total_files,
            "total_size_mb": total_size,
            "average_size_mb": total_size / total_files,
            "formats_used": list(set(file["format"] for file in self.processed_files))
        }
    
    # Class method - operates on the class itself, has access to cls
    @classmethod
    def create_batch_processor(cls, batch_name, batch_size=1000):
        """
        Class method to create a specialized batch processor.
        Alternative constructor pattern.
        
        Args:
            batch_name (str): Name for the batch processor
            batch_size (int): Size of batches to process
            
        Returns:
            DataProcessor: New instance configured for batch processing
        """
        processor = cls(f"BatchProcessor_{batch_name}", "parquet", batch_size)
        processor.batch_size = batch_size  # Add extra attribute
        print(f"Created batch processor with batch size: {batch_size}")
        return processor
    
    # Static method - doesn't need instance or class, utility function
    @staticmethod
    def validate_file_format(file_path):
        """
        Static method to validate if a file format is supported.
        Utility function that doesn't need instance or class data.
        
        Args:
            file_path (str): Path to file to validate
            
        Returns:
            bool: True if format is supported, False otherwise
        """
        if not file_path:
            return False
        
        extension = file_path.split('.')[-1].lower()
        return extension in DataProcessor.supported_formats
    
    # Special method (dunder method) - defines string representation
    def __repr__(self):
        """
        Official string representation of the object.
        Should be unambiguous and ideally evaluable.
        """
        return f"DataProcessor(name='{self.name}', format='{self.default_format}')"
    
    def __str__(self):
        """
        Informal string representation of the object.
        Should be readable and user-friendly.
        """
        return f"DataProcessor '{self.name}' - {len(self.processed_files)} files processed"

# Demonstrate class usage
print("=== Class Usage Examples ===")

# Create instances using regular constructor
processor1 = DataProcessor("ETL_Processor", "json", 500)
processor2 = DataProcessor("Analytics_Processor", "parquet", 1000)

# Create instance using class method (alternative constructor)
batch_processor = DataProcessor.create_batch_processor("Daily_Batch", 2000)

# Demonstrate instance methods

result2 = processor1.process_file("/data/customers.csv", "csv")

print(f"\nProcessing results:")
print(f"Result 1: {result1}")
print(f"Result 2: {result2}")

# Get statistics
stats = processor1.get_processing_stats()
print(f"\nProcessing statistics: {stats}")

# Demonstrate static method (can be called on class or instance)
print(f"\nValidation tests:")
print(f"sales.json is valid: {DataProcessor.validate_file_format('sales.json')}")
print(f"data.txt is valid: {DataProcessor.validate_file_format('data.txt')}")

# Demonstrate class vs instance variables
print(f"\nClass variable access:")
print(f"Total processors created: {DataProcessor.total_processors_created}")
print(f"Supported formats: {DataProcessor.supported_formats}")

# String representations
print(f"\nString representations:")
print(f"repr(processor1): {repr(processor1)}")
print(f"str(processor1): {str(processor1)}")

# Demonstrate attribute access
print(f"\nInstance attributes:")
print(f"processor1.name: {processor1.name}")
print(f"processor1.processed_files: {len(processor1.processed_files)} files")
  • Class: Blueprint/template for creating objects with shared structure
  • __init__: Constructor method that initializes new instances
  • self: Reference to the current instance, always first parameter in instance methods
  • Instance variables: Attributes unique to each object instance
  • Class variables: Attributes shared by all instances of the class
  • Instance methods: Functions that operate on instance data (have self parameter)
  • Class methods: Functions that operate on class data (have cls parameter, use @classmethod)
  • Static methods: Utility functions that don't need instance or class data (use @staticmethod)

Identity vs Equality: is vs ==

Understanding the difference between identity (is) and equality (==) is crucial for avoiding bugs, especially with mutable objects and singleton objects.

# Comprehensive demonstration of identity vs equality

print("=== IDENTITY vs EQUALITY ===")

# === Basic equality vs identity ===
a = [1, 2, 3]
b = [1, 2, 3]  # Same content, different objects
c = a          # Same object reference

print(f"Lists: a={a}, b={b}, c={c}")
print(f"a == b (equality): {a == b}")      # True - same content
print(f"a is b (identity): {a is b}")      # False - different objects
print(f"a is c (identity): {a is c}")      # True - same object
print(f"id(a): {id(a)}, id(b): {id(b)}, id(c): {id(c)}")

# === Modifications and identity ===
print("\nAfter modifying a:")

# === Practical implications ===
print("\n=== Practical Implications ===")

def dangerous_default_argument(item, target_list=[]):
    """
    Dangerous: mutable default argument
    The same list object is reused across calls!
    """
    target_list.append(item)
    return target_list

def safe_default_argument(item, target_list=None):
    """
    Safe: create new list for each call when needed
    """
    if target_list is None:
        target_list = []
    target_list.append(item)
    return target_list

# Demonstrate the problem
result1 = dangerous_default_argument("first")
result2 = dangerous_default_argument("second")
print(f"Dangerous function results:")
print(f"First call: {result1}")
print(f"Second call: {result2}")  # Contains both items!
print(f"Same object: {result1 is result2}")

# Demonstrate the solution
result3 = safe_default_argument("first")
result4 = safe_default_argument("second") 
print(f"\nSafe function results:")
print(f"First call: {result3}")
print(f"Second call: {result4}")  # Contains only its own item
print(f"Same object: {result3 is result4}")

# === Best practices ===
print("\n=== Best Practices ===")
print("1. Use == for value comparison")
print("2. Use is for identity comparison (especially with None, True, False)")
print("3. Always use 'is None' instead of '== None'")
print("4. Be careful with mutable default arguments")
print("5. Understand that small integers and strings may be cached/interned")
  • == (equality): Compares values/content of objects
  • is (identity): Compares object identity (same object in memory)
  • id() function: Returns unique identifier for objects (memory address)
  • Singleton objects: None, True, False always have same identity
  • Small integer caching: Python caches integers -5 to 256 for efficiency
  • String interning: Python may reuse identical string objects
  • Mutable default args: Dangerous pattern that reuses same object across calls
