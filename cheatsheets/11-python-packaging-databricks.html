🏗️ Project Structure Setup

▼

Setting up a proper Python package structure for Databricks deployment. This structure ensures your code is modular, testable, and easily deployable across different environments.

Standard Package Structure

my_databricks_package/
├── pyproject.toml          # Modern Python packaging configuration
├── setup.cfg              # Alternative/additional configuration
├── setup.py               # Build script (optional with pyproject.toml)
├── README.md              # Package documentation
├── LICENSE                # License file
├── .gitignore            # Git ignore patterns
├── requirements.txt       # Runtime dependencies
├── requirements-dev.txt   # Development dependencies
├── src/                   # Source code directory
│   └── my_package/
│       ├── __init__.py
│       ├── core/
│       │   ├── __init__.py
│       │   ├── data_processing.py
│       │   └── utils.py
│       ├── spark/
│       │   ├── __init__.py
│       │   ├── etl.py
│       │   └── transformations.py
│       └── config/
│           ├── __init__.py
│           └── settings.py
├── tests/                 # Test directory
│   ├── __init__.py
│   ├── conftest.py       # Pytest configuration
│   ├── test_core/
│   └── test_spark/
├── notebooks/             # Example notebooks
│   └── examples/
└── scripts/              # Utility scripts
    ├── build.sh
    └── deploy.sh
  • What it does: Provides a standardized, maintainable project structure
  • When to use: For any reusable code that will be shared across notebooks or clusters
  • Best practice: Keep source code in src/ directory to avoid import issues
  • Databricks tip: Use meaningful package names that reflect your organization

🔨 Building and Installing Packages

▼

Step-by-step process for building distributable packages and installing them in various Databricks environments. Understanding different installation methods is crucial for deployment flexibility.

Building Packages Locally

# Install build tools
pip install build twine

# Build the package (creates dist/ directory)
python -m build

# This creates:
# dist/
# ├── my_databricks_package-0.1.0-py3-none-any.whl  # Wheel distribution
# └── my_databricks_package-0.1.0.tar.gz            # Source distribution

# Install locally for testing
pip install -e .  # Editable install (development mode)
pip install .     # Regular install

# Install with optional dependencies
pip install -e .[dev,ml]  # Install with dev and ml extras
  • What it does: Creates distributable package files (wheel and source)
  • Editable install: Changes to source code are immediately reflected
  • Wheel format: Faster installation and cross-platform compatibility
  • Testing: Always test locally before deploying to Databricks

Databricks Installation Methods

# Method 1: Install from DBFS
%pip install /dbfs/path/to/your/package.whl

# Method 2: Install from Workspace Files
%pip install /Workspace/Repos/your-repo/dist/package.whl

# Method 3: Install from PyPI (if published)
%pip install my-databricks-package

# Method 4: Install from Git repository
%pip install git+https://github.com/your-org/my-databricks-package.git

# Method 5: Install from local directory in Repos
%pip install /Workspace/Repos/your-repo/my-databricks-package/

# Install with specific extras
%pip install /dbfs/path/to/package.whl[ml,viz]

# Restart Python to ensure imports work
dbutils.library.restartPython()
  • DBFS method: Upload wheel to DBFS, accessible across clusters
  • Repos method: Direct install from Git-integrated workspace
  • Git install: Always pulls latest code, good for CI/CD
  • Important: Always restart Python after package installation

Cluster-Level Installation

# Install on cluster startup via init script
# Create init script: /dbfs/scripts/install_packages.sh

#!/bin/bash
pip install /dbfs/packages/my-databricks-package-0.1.0-py3-none-any.whl

# Or via cluster libraries UI:
# 1. Go to cluster configuration
# 2. Libraries tab
# 3. Install New > Upload > Python Whl
# 4. Upload your .whl file

# Programmatic cluster library installation
from databricks_cli.sdk.api_client import ApiClient
from databricks_cli.clusters.api import ClusterApi

api_client = ApiClient(
    host="https://your-workspace.cloud.databricks.com",
    token="your-access-token"
)

clusters_api = ClusterApi(api_client)

# Install library on cluster
library_config = {
    "whl": "/dbfs/path/to/package.whl"
}

clusters_api.install_libraries("cluster-id", [library_config])
  • Init script: Packages installed automatically when cluster starts
  • UI method: Easy for manual installation and testing
  • Programmatic: Useful for automated deployments and CI/CD
  • Persistence: Cluster libraries persist across restarts

DBFS Storage Strategy

# Upload package to DBFS
dbutils.fs.cp("file:/local/path/package.whl", "/dbfs/shared/packages/")

# Install from DBFS location
%pip install /dbfs/shared/packages/my-databricks-package-0.1.0-py3-none-any.whl

# Create shared location for team packages
# /dbfs/shared/packages/
# ├── my-package-v1.0.0.whl
# ├── another-package-v2.1.0.whl
# └── common-utils-v0.5.0.whl

# Automated upload script
import subprocess
import os

def upload_package_to_dbfs(wheel_path, dbfs_target="/dbfs/shared/packages/"):
    """Upload Python wheel to DBFS"""
    
    # Get wheel filename
    wheel_name = os.path.basename(wheel_path)
    dbfs_path = os.path.join(dbfs_target, wheel_name)
    
    # Copy to DBFS
    dbutils.fs.cp(f"file:{wheel_path}", dbfs_path)
    
    print(f"Uploaded {wheel_name} to {dbfs_path}")
    return dbfs_path

# Usage
wheel_path = "/local/build/dist/my-package-1.0.0-py3-none-any.whl"
dbfs_path = upload_package_to_dbfs(wheel_path)
  • Shared access: All cluster users can access packages from DBFS
  • Persistence: Packages persist across cluster restarts
  • Version management: Can maintain multiple versions simultaneously
  • Storage cost: DBFS storage incurs costs but provides reliability

Import Best Practices

# ✅ Good: Explicit imports with error handling
try:
    from my_package.spark.etl import ETLProcessor
    from my_package.core.config import load_config
    from my_package.utils.helpers import validate_schema
    print("✅ Package imported successfully")
except ImportError as e:
    print(f"❌ Import error: {e}")
    print("Please ensure the package is installed: %pip install my-databricks-package")

# ✅ Good: Version checking
try:
    import my_package
    print(f"Package version: {my_package.__version__}")
    
    # Check minimum version
    from packaging import version
    required_version = "1.0.0"
    if version.parse(my_package.__version__) < version.parse(required_version):
        raise ImportError(f"Package version {my_package.__version__} < required {required_version}")
        
except ImportError as e:
    print(f"Version check failed: {e}")

# ✅ Good: Conditional imports for optional features
def load_ml_models():
    try:
        from my_package.ml import ModelFactory
        return ModelFactory()
    except ImportError:
        print("ML features not available. Install with: %pip install my-package[ml]")
        return None

# ✅ Good: Lazy imports for performance
class DataProcessor:
    def __init__(self):
        self._spark_utils = None
    
    @property
    def spark_utils(self):
        if self._spark_utils is None:
            from my_package.spark.utils import SparkUtils
            self._spark_utils = SparkUtils()
        return self._spark_utils

# ❌ Bad: Wildcard imports
# from my_package.spark import *  # Avoid this

# ❌ Bad: Hardcoded paths
# sys.path.append("/dbfs/specific/user/path")  # Not portable
  • Error handling: Graceful handling of missing packages
  • Version checking: Ensures compatibility across environments
  • Conditional imports: Allows optional features without breaking core functionality
  • Lazy imports: Improves startup performance by loading modules when needed

        file: ./coverage.xml

  build:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: ${{ env.PYTHON_VERSION }}
    
    - name: Install build tools
      run: |
        python -m pip install --upgrade pip
        pip install build
    
    - name: Build package
      run: python -m build
    
    - name: Upload artifacts
      uses: actions/upload-artifact@v3
      with:
        name: dist
        path: dist/

  deploy-to-databricks:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Download artifacts
      uses: actions/download-artifact@v3
      with:
        name: dist
        path: dist/

Deployment Script

# scripts/deploy.py - Custom deployment script
import os
import sys
import subprocess
import argparse
from pathlib import Path

class DatabricksDeployer:
    def __init__(self, workspace_url, token, package_path):
        self.workspace_url = workspace_url
        self.token = token
        self.package_path = Path(package_path)
        
    def deploy_package(self, target_path="/shared/packages/"):
        """Deploy package to Databricks DBFS"""
        
        print(f"🚀 Deploying {self.package_path.name} to Databricks...")
        
        # Build package if needed
        if not self.package_path.exists():
            self.build_package()
        
        # Upload to DBFS
        dbfs_path = f"dbfs:{target_path}{self.package_path.name}"
        
        upload_cmd = [
            "databricks", "fs", "cp",
            str(self.package_path),
            dbfs_path,
            "--overwrite"
        ]
        
        try:
            result = subprocess.run(upload_cmd, check=True, capture_output=True, text=True)
            print(f"✅ Successfully deployed to {dbfs_path}")
            return dbfs_path
        except subprocess.CalledProcessError as e:
            print(f"❌ Deployment failed: {e.stderr}")
            sys.exit(1)
    
    def build_package(self):
        """Build the package using build tool"""
        print("🔨 Building package...")
        
        build_cmd = ["python", "-m", "build"]
        
        try:
            subprocess.run(build_cmd, check=True, cwd=self.package_path.parent)
            print("✅ Package built successfully")
        except subprocess.CalledProcessError as e:
            print(f"❌ Build failed: {e}")
            sys.exit(1)
    
    def install_on_cluster(self, cluster_id):
        """Install package on specific cluster"""
        print(f"📦 Installing package on cluster {cluster_id}...")
        
        dbfs_path = self.deploy_package()
        
        install_cmd = [
            "databricks", "libraries", "install",
            "--cluster-id", cluster_id,
            "--whl", dbfs_path
        ]
        
        try:
            subprocess.run(install_cmd, check=True)
            print(f"✅ Package installed on cluster {cluster_id}")
        except subprocess.CalledProcessError as e:
            print(f"❌ Installation failed: {e}")
            sys.exit(1)

def main():
    parser = argparse.ArgumentParser(description="Deploy package to Databricks")
    parser.add_argument("--workspace", required=True, help="Databricks workspace URL")
    parser.add_argument("--token", required=True, help="Databricks access token")
    parser.add_argument("--package", required=True, help="Path to package wheel")
    parser.add_argument("--cluster", help="Cluster ID to install on")
    
    args = parser.parse_args()
    
    deployer = DatabricksDeployer(args.workspace, args.token, args.package)
    
    if args.cluster:
        deployer.install_on_cluster(args.cluster)
    else:
        deployer.deploy_package()

if __name__ == "__main__":
    main()
  • Automated deployment: Handles building, uploading, and installation
  • Error handling: Provides clear feedback on deployment status
  • Flexible deployment: Can deploy to DBFS or install on clusters
  • CLI integration: Uses Databricks CLI for reliable operations
